## Conclusion

- The N1 lead is **confirmed**: MLBB caches absolute paths in its preferences and in `base_loadres_version_info`, and every one names the instance's own root.
- Copying any of these files into another instance would plant the wrong root. The Sharing Profile keeps all preferences and metadata private, and T10 must run this scan on B and find none of A's paths.
- `_finish` (the "download complete" marker) is present on the host but **absent on A**, matching the plan's hypothesis.
- No path in clone A names the host MLBB root (`/storage/emulated/0/Android/data/com.mobile.legends/...`), so the clone is not writing into the host's tree.
