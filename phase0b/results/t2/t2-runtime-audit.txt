**Conclusions:**

- The spoofing is exactly as narrow as the audit said: only callers of the **old** `__system_property_get` see Pixel 6 / Android 12. Java `Build`, the modern native API and child processes all see the real Samsung values. This is the inconsistent picture described in Section 3.7 of the plan.
- **`ANDROID_ID` is identical in the normal app, User 0 and User 1.** The clone does not get a per-instance ID. For MLBB or Instagram, two clones (and the real app) would look like the same device install — the N6 identity link, confirmed at the mechanism level.
- `RLIMIT_NOFILE` is the same inside the guest as outside (32768 soft), so the handle budget is not reduced by the engine.

## 3. Hard-coded-path escape test (step 3)

`escape dataData.open=DENIED errno=13 (Permission denied); sdcard.open=ALLOWED wrote=1`

- `open("/data/data/dev.dualapp.canary/files/x", O_RDWR|O_CREAT)` → **DENIED** (`EACCES`), as expected: the real app's data dir belongs to a different UID.
- `open("/sdcard/Download/.dualapp-escape-test", O_WRONLY|O_CREAT|O_TRUNC)` → **ALLOWED**, one byte written, file deleted immediately. The engine's All Files Access lets a guest's **native** code reach real shared storage with a hard-coded path. This confirms the risk-20 hypothesis: libc-level `/sdcard` redirection is missing.

## 4. New engine issue: the `:black` process is frozen and killed

- `02:48:13 am_kill : [0,23238,top.niunaijun.blackbox:black,...,Sync transaction while frozen]`
- `02:57:51` and `03:04:51` the same, with the guest running.
- The guest's binder call gets `BR_FROZEN_REPLY` / `FAILED BINDER TRANSACTION`, then `DeadObjectException` in `BlackManager.getPackageInfo`.
- Cause: `:black` is a cached background process. Android's app freezer freezes it, and the system kills it when a sync binder transaction arrives instead of unfreezing it.
- Consequence seen: a guest `startActivity` could not resolve its target, the raw intent reached the real system, and the guest died with `SecurityException: not exported from uid 10034` followed by an input-dispatch ANR.
- This is an engine robustness bug for T12/T13. A fix needs `:black` to stay unfrozen (foreground service, a binding from the guest/UI, or a freezer exemption). It is not a Canary bug.
