## 6. Crash while opening the env page (new finding)

Canary v0.3 was installed as an update (versionCode 3, data kept) and the clone relaunched. The "Open env page" button click crashed the guest. Two engine issues appeared in the same 15-second window.

### 6.1 The engine's `:black` process is frozen and killed by Android 17

- `02:48:13 am_kill : [0,23238,top.niunaijun.blackbox:black,...,Sync transaction while frozen]` (first launch).
- `02:57:51` the same for PID 23851, while the guest was running.
- The guest's binder call got `BR_FROZEN_REPLY` / `FAILED BINDER TRANSACTION`, then `DeadObjectException` in `BlackManager.getPackageInfo`.
- Cause: `:black` is a cached background process. Android's app freezer freezes it, and the system kills it when a sync binder transaction arrives instead of unfreezing it.
- Consequence: any guest operation that needs a virtual service at that moment fails. Here it broke activity resolution.

### 6.2 Starting a second guest activity fails with SecurityException

- The Canary button called `startActivity(EnvActivity)`.
- `ActivityManagerCommonProxy$StartActivity.hook` resolves the target through `BlackBoxCore.getBPackageManager().resolveActivity(...)`.
- With `:black` dead, resolution returned null, so the hook fell through to the real `IActivityManager.startActivity` with the raw guest intent.
- The real system refused: `SecurityException: Permission Denial: starting Intent { cmp=dev.dualapp.canary/.EnvActivity } ... not exported from uid 10034`.
- The `FATAL EXCEPTION` killed the guest main thread; the system then reported an input-dispatch ANR (`02:58:04`) and killed the process (`02:59:40`).

**Open question:** does resolution also fail when `:black` is alive, because `EnvActivity` was added to the host APK after the clone was installed? The clone's component list is registered at install time. This needs a retest; the phone locked (screen timeout) before it could run.
